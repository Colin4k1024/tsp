# Grok Hook 适配审查报告

## 审查范围

对比 Grok Build 官方 Hook 能力清单，审查当前 TSP 项目的 Grok hook 适配实现。

---

## 一、核心问题清单

### 问题 1: 事件名映射错误（严重）

**官方规范：** Grok 使用与 Claude Code 完全一致的事件名：`SessionStart`, `SessionEnd`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `PermissionDenied`, `Stop`, `StopFailure`, `Notification`, `SubagentStart`, `SubagentStop`, `PreCompact`, `PostCompact`

**当前实现：** `.grok/hook-compatibility-analysis.md` 和 `grok-event-bridge.js` 使用了一套**不存在的** Grok 事件名：

| TSP 映射到的事件名 | 官方是否存在 | 正确的事件名 |
|---|---|---|
| `context` | 不存在 | `SessionStart` |
| `observation` | 不存在 | `PostToolUse` |
| `summarize` | 不存在 | `Stop` |
| `file-context` | 不存在 | `PreToolUse` |
| `session-init` | 不存在 | `UserPromptSubmit` |
| `user-message` | 不存在 | `UserPromptSubmit` |
| `file-edit` | 不存在 | `PostToolUse` (Edit 工具) |

**影响：**
- `grok-event-bridge.js:20-26` 的 `EVENT_MAP` 映射到不存在的事件名
- `grok-packager.js:336-343` 生成的默认 `hooks.json` 使用不存在的事件名（`context`, `observation`, `summarize`, `file-context`）
- 兼容性分析文档（`.grok/hook-compatibility-analysis.md`）全部基于错误的事件名
- 能力矩阵（`.grok/matrix/capability-matrix.md`）的事件映射也是错误的

**涉及文件：**
- `scripts/grok/grok-event-bridge.js:20-26`
- `scripts/grok/grok-packager.js:336-343`
- `.grok/hook-compatibility-analysis.md`（全文）
- `.grok/matrix/capability-matrix.md:58-61`
- `.grok/compatibility-table.md`

---

### 问题 2: 工具名映射可能造成双重映射（中等）

**官方规范：** "Claude tool names such as `Bash`, `Read`, and `Edit` are mapped to Grok's automatically" — Grok 内部自动处理工具名映射。

**当前实现：** `grok-event-bridge.js:36-44` 和 `grok-hook-wrapper.js:34-42` 手动将 `Bash`→`bash`, `Read`→`read` 等。如果 Grok 已经做了自动映射，我们的二次映射会导致：
- Grok 输入 `Bash` → 我们转成 `bash` → Grok 再映射一次 → 结果不可预期

**建议：** 移除自定义工具名映射，信任 Grok 的自动映射。

**涉及文件：**
- `scripts/grok/grok-event-bridge.js:36-44` (`TOOL_NAME_MAP`)
- `scripts/grok/grok-hook-wrapper.js:34-42` (`TOOL_NAME_MAP`)

---

### 问题 3: 环境变量不匹配（中等）

**官方规范：** 每个 hook 进程接收以下环境变量：
- `GROK_HOOK_EVENT` — 当前事件名
- `GROK_HOOK_NAME` — hook 名称
- `GROK_SESSION_ID` — 会话 ID
- `GROK_WORKSPACE_ROOT` — 工作区根目录

**当前实现：** 使用了不同的环境变量：
- `GROK_HOME` — 非官方规范
- `GROK_MODEL` — 非官方规范
- `PROJECT_ROOT` — 非官方规范（应为 `GROK_WORKSPACE_ROOT`）
- `TSP_HOME` — TSP 自定义

**影响：**
- `path-resolver.js:20` 依赖 `GROK_HOME` 做平台检测，但官方不保证设置此变量
- `grok-cost-tracker.js:62` 读取 `GROK_SESSION_ID`（这个是正确的）
- `grok-cost-tracker.js:58` 读取 `GROK_MODEL`（非官方变量）
- `grok-event-bridge.js:76-78` 设置 `GROK_HOME`, `PROJECT_ROOT`, `TSP_HOME`

**建议：**
- 平台检测应改用 `GROK_HOOK_EVENT` 或 `GROK_WORKSPACE_ROOT`
- 使用 `GROK_WORKSPACE_ROOT` 替代 `PROJECT_ROOT`
- 保留 `GROK_HOME` 作为回退（Grok 可能设置），但不作为主要检测手段

---

### 问题 4: stdin 输入格式不一致（中等）

**官方规范：** 事件 JSON 包含 `hookEventName`, `sessionId`, `cwd`, `workspaceRoot`，工具事件还有 `toolName` 和 `toolInput`。

**当前实现：** 各 hook 脚本读取的字段名不一致：

| Hook | 读取的字段 | 问题 |
|---|---|---|
| `grok-session-start.js:29` | `session_id`, `sessionId` | 应读 `sessionId`（camelCase） |
| `grok-session-end.js:27` | `session_id`, `sessionId` | 同上 |
| `grok-pre-bash-block-no-verify.js:32-35` | `tool_input.command`, `toolInput.command` | 应读 `toolInput.command`（camelCase） |
| `grok-post-bash-command-log.js:65-66` | `tool_input.command`, `toolInput.command` | 同上 |
| `grok-cost-tracker.js:50-51` | `usage`, `token_usage` | 非标准字段 |

**建议：** 统一使用官方 camelCase 格式：`sessionId`, `toolName`, `toolInput`, `hookEventName`

---

### 问题 5: PreToolUse 阻断输出格式不完全符合规范（低）

**官方规范：**
```json
{ "decision": "deny", "reason": "Unsafe command detected" }
```
Exit code 0 allows, exit code 2 denies.

**当前实现：** `grok-pre-bash-block-no-verify.js:48-53` 使用 `process.exit(2)` 阻断，但 stdout 输出的是原始输入 JSON 而不是 `{"decision":"deny","reason":"..."}` 格式。

**影响：** 虽然 exit code 2 正确，但 stdout 格式不规范。Grok 可能忽略 stdout（因为 exit code 已经表达决策），但不符合最佳实践。

**建议：** stdout 输出应改为 `{"decision":"deny","reason":"..."}` 格式。

---

### 问题 6: SessionEnd 事件映射为 Stop（中等）

**官方规范：** `SessionEnd` 和 `Stop` 是两个独立事件：
- `Stop` — 一个 turn 结束时触发
- `SessionEnd` — 整个会话结束时触发

**当前实现：** `grok-session-end.js:42` 输出 `hookEventName: 'Stop'`，将 SessionEnd 映射为 Stop。这意味着：
- 会话结束时的清理逻辑会在每个 turn 结束时也被触发（如果注册为 Stop hook）
- 丢失了 SessionEnd 的独有语义

**建议：** 应该使用 `hookEventName: 'SessionEnd'`。

---

### 问题 7: 事件覆盖不完整（低）

**官方支持 14 个事件，当前仅适配 5 个：**

| 事件 | 是否适配 | 备注 |
|---|---|---|
| `SessionStart` | 有 | `grok-session-start.js` |
| `SessionEnd` | 有（但映射为 Stop） | `grok-session-end.js` |
| `PreToolUse` | 有 | `grok-pre-bash-block-no-verify.js` |
| `PostToolUse` | 有 | `grok-post-bash-command-log.js` |
| `Stop` | 无独立实现 | 被 SessionEnd 占用 |
| `UserPromptSubmit` | 无 | 兼容性分析提到但未实现 |
| `PostToolUseFailure` | 无 | |
| `PermissionDenied` | 无 | |
| `StopFailure` | 无 | |
| `Notification` | 无 | |
| `SubagentStart` | 无 | |
| `SubagentStop` | 无 | |
| `PreCompact` | 无 | 兼容性分析标记为"无直接映射" |
| `PostCompact` | 无 | |

---

### 问题 8: plugin.json hooks 数组为空（低）

**当前实现：** `.grok-plugin/plugin.json:20` 声明 `"hooks": true` 但 `"hooks": []`。

**packager 实现：** `grok-packager.js:235` 生成 `"hooks": "hooks.json"`（指向文件），但 `.grok-plugin/plugin.json` 中是空数组。

**建议：** 确保 packager 生成的 manifest 正确引用 hooks 配置。

## 二、修复方案

### Phase 1: 修正事件名映射（关键路径）

1. **`scripts/grok/grok-event-bridge.js`** — 修正 `EVENT_MAP`：
   ```js
   const EVENT_MAP = {
     pre_tool_use: 'PreToolUse',
     post_tool_use: 'PostToolUse',
     post_tool_use_failure: 'PostToolUseFailure',
     session_start: 'SessionStart',
     session_end: 'SessionEnd',
     stop: 'Stop',
     user_prompt_submit: 'UserPromptSubmit',
     pre_compact: 'PreCompact',
     post_compact: 'PostCompact',
     permission_denied: 'PermissionDenied',
     notification: 'Notification',
     subagent_start: 'SubagentStart',
     subagent_stop: 'SubagentStop',
   };
   ```

2. **`scripts/grok/grok-packager.js:336-343`** — 修正默认 hooks.json 使用官方事件名

3. **`.grok/hook-compatibility-analysis.md`** — 重写事件映射表

4. **`.grok/matrix/capability-matrix.md`** — 修正事件名

### Phase 2: 移除不必要的工具名映射

1. **`scripts/grok/grok-event-bridge.js`** — 移除 `TOOL_NAME_MAP`，直接传递原始工具名
2. **`scripts/grok/grok-hook-wrapper.js`** — 同上

### Phase 3: 修正环境变量

1. **`scripts/grok/path-resolver.js`** — 平台检测改用 `GROK_HOOK_EVENT` 或 `GROK_WORKSPACE_ROOT`
2. **`scripts/grok/hooks/grok-cost-tracker.js`** — 使用 `GROK_SESSION_ID`（已正确），移除 `GROK_MODEL` 依赖或改用官方变量
3. **`scripts/grok/grok-event-bridge.js`** — 使用 `GROK_WORKSPACE_ROOT` 替代 `PROJECT_ROOT`

### Phase 4: 修正 stdin 格式和输出格式

1. **所有 grok hook 脚本** — 统一使用 camelCase 字段名（`sessionId`, `toolName`, `toolInput`）
2. **`grok-pre-bash-block-no-verify.js`** — stdout 输出改为 `{"decision":"deny","reason":"..."}` 格式
3. **`grok-session-end.js`** — `hookEventName` 改为 `'SessionEnd'`

### Phase 5: 补充缺失事件适配（可选）

按优先级补充：
1. `Stop` — 独立的 turn 结束处理（当前被 SessionEnd 占用）
2. `UserPromptSubmit` — 用户消息处理
3. `PostToolUseFailure` — 工具失败处理
4. `PreCompact` — 压缩前状态保存
